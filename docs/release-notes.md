# Kinbo 0.4.5

修复覆盖更新后的菜单残留，并补上 macOS 后台自动启动。配套 Zotero 插件为 **4.1.7.17**。

## 本次更新

- 清理旧版遗留的 Kinbo / PDF2zh 双菜单和旧阅读入口；只保留四个翻译命令与一个「深度阅读 / 停止阅读」。
- macOS 使用用户级 LaunchAgent 自动启动；首次找不到旧后台时，在 Zotero 中选一次原后台文件夹，之后自动唤醒，无需输入命令。
- Windows 连接失败时尝试唤醒已有的 Kinbo 计划任务。连接未就绪时给出提示，不直接打开无法访问的浏览器页面。
- Mac 新用户可双击 install-macos.command，自动准备独立 Python、安装并检查后台、配置登录启动，再从 Zotero 插件管理器安装选中的 XPI。
- 修正 POSIX 虚拟环境 Python 路径与健康服务版本判断；Reader 清理出错仍继续清理菜单，停用后异步返回不再注入界面。

## 已有用户更新

在 Zotero「工具 → 插件 → 齿轮 → 检查更新」中安装新版，然后完全退出并重开 Zotero。也可从本页下载 XPI 覆盖安装，无需卸载旧插件或重新填写 API。

如果 Mac 提示关联后台，选择原安装中包含 server.py 的文件夹。已有端口（例如 8892）、Python 环境、模型配置和论文继续使用。尚未安装后台的新电脑先运行完整 ZIP 中对应系统的安装器。

0.4.1 及更新后台可通过 XPI 中的 0.4.5 源码包同步，等待翻译、阅读及对话空闲后更新，启动检查失败回滚。0.3.x / 0.4.0pre1 仍需先按 README 完成一次更新接口迁移。远程 / HTTPS 后台和本机源码改动不由自动唤醒流程重写。

## 保留的工作流

后台 Web 控制页、翻译引擎、完整 PDF / 全部页面阅读、Codex 登录、共享 API、论文会话、原文定位和笔记归档保持现有流程。插件 ID、设置命名空间、更新地址与生产数据格式不变。

自动验证使用合成内容和模拟模型接口；Windows 原生 Zotero 升级 / Reader 验证使用隔离资料库。macOS 系统启动测试与原生 Zotero 界面测试分开记录，不将跨平台单元测试等同于 Mac 实机 Zotero 验收。
